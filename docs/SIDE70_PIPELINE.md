## 650步截断与动作块诊断

2026-11-09用户反馈episode-001视觉上已入盒，001–004起始等待过长。已对原动作回放并以原20k检查点做独立在线对照，成功谓词未改变：

| 诊断配置（相同种子20000–20002） | 成功数 | 观察 |
|---|---|---|
| 原650步上限、执行5步 | 0/3 | 截自原20条正式评测 |
| 1000步上限、执行5步 | 1/3 | episode-001在735步通过所有条件 |
| 1000步上限、执行20步 | 0/3 | 起步提前，但没有改善这组抓取放置结果 |

原001动作回放到650步时，inside/supported/released为true，线速度和角速度稳定窗口为false。视觉上的放入与连续1秒稳定判定有时间差；因此原0/20不能解释为模型完全不会完成该任务。在线对照包含物理重置/接触微小差异，不宣称与原轨迹逐位相同。

模型预测20步，但原先只执行前5步；实测首块前5步近乎保持位置，后半段才出现明显运动指令。反复重规划会重复等待前缀。20步执行块将这组三个种子的明显运动指令起点提前到0.20–0.32秒，原5步执行块为约5.2–8.2秒。然而更长的连续执行也改变反馈频率，当前不能直接设为默认。

已修复仿真任务内硬编码650的问题，使其实际遵循RLinf的max_episode_steps；默认650和正式DSRL配置暂未改变。新增物理判定子条件与最大角速度日志，解决原生包装器丢弃task infos后无法定位失败原因的问题。20项轻量测试、12项原成功判定测试及实际1000步仿真验证通过。

诊断产物位于同一实验目录下：`diagnostic-replay/`、`diagnostic-1000-v2/`、`diagnostic-chunk20/`。第1次1000步诊断因跨进程诊断字段读取错误退出，保留在`diagnostic-1000/`，不作为结果。上述3条诊断不是正式20种子基线，未据此启动RL。
